\begin{abstract}
We benchmark six LiDAR-only detector configurations on Boreas-Objects-V1 using one seed-42 epoch-80 checkpoint per model and a common 1,326-frame validation set. Accuracy is evaluated with local 3D AP40, recall, range, and fixed point-count cohorts; efficiency uses preprocessing-inclusive FP32 latency and memory. Robustness is tested without retraining through nested 128/64/32/16-ring subsets and elevation-matched VLP-16/VLP-32C profiles. PV-RCNN has the highest dense mAP40 (59.11\%) but requires 310.81 ms per prepared frame. SECOND is fastest (40.87 ms, 48.50\% mAP), while PointPillars Lite reaches 49.66\% at 46.32 ms with 74.82\% fewer parameters than PointPillars. At modulo-16 phase zero, only 13.51--30.79\% of dense mAP remains and Pedestrian recall falls to 14.57--32.01\%. Across all valid modulo offsets, 16-ring mean mAP ranges from 7.17\% to 20.03\%, and within-model min--max spreads reach 3.88--7.20 points. PointPillars leads the VLP-16 angular subset, whereas PV-RCNN remains best for VLP-32C. The contribution is a traceable joint analysis of accuracy, efficiency, object support, and two disclosed sparsity interventions on a common split. Results are descriptive because each configuration has one training realization; phase dispersion quantifies paired input-offset sensitivity, not training uncertainty.
\end{abstract}
\noindent\textbf{Keywords:} 3D object detection; LiDAR; Boreas; benchmarking; latency; beam sparsity; elevation sampling; recall.

\section{Introduction}
LiDAR-based three-dimensional object detection estimates object categories, positions, dimensions, and orientations from point clouds. Its practical use requires more than a high aggregate accuracy score: a detector must also fit the available memory and process observations within an acceptable time budget. Established architectures make different choices about spatial discretization, feature extraction, prediction heads, and proposal refinement. PointPillars, SECOND, CenterPoint, VoxelNeXt, and PV-RCNN exemplify these choices \cite{lang2019pointpillars,yan2018second,yin2021centerpoint,chen2023voxelnext,shi2020pvrcnn}. Comparing their published scores directly does not isolate their behavior on the same data, implementation, and hardware.

Boreas offers an opportunity to examine detection with dense 128-channel LiDAR observations \cite{burnett2023boreas}. However, using a dataset with multiple seasons does not automatically constitute an evaluation of detection across seasons. Our experiments use Boreas-Objects-V1 and its existing detection annotations; the weather coverage of these annotations defines the scope of our claims. We investigate detector accuracy, computational cost, distance dependence, and sensitivity to deterministic ring removal and elevation-matched angular profiles within this scope.

Distance and sampling density are complementary sources of variation. Objects farther from the sensor generally occupy fewer measured points, while removing rings changes the available vertical sampling throughout the scene. The effect depends on object geometry, occlusion, and the detector configuration. Prior work has already investigated beam-induced domain gaps and corruption robustness \cite{wei2022lidardistillation,griesbacher2025beamdensity,kong2023robo3d,dong2023corruptions}. Consequently, our contribution is a reproducible, dataset-specific evaluation protocol and a joint analysis of several operating criteria. We make no claim to introduce beam-density evaluation itself.

The benchmark addresses four research questions:
\begin{enumerate}
\item \textbf{RQ1: Accuracy.} How do the six configurations compare in overall and class-specific 3D detection accuracy on nominal 128-beam Boreas-Objects-V1 input?
\item \textbf{RQ2: Efficiency.} What batch-one latency, memory, and parameter costs accompany their accuracy, and which configurations are Pareto efficient under the measured operating conditions?
\item \textbf{RQ3: Range.} How do class-specific accuracy and detector rankings vary across radial distance bands, and how does recall vary with the number of points inside an object?
\item \textbf{RQ4: Sparsity.} How do AP, recall, and model ordering change when a dense-trained checkpoint is evaluated on deterministic 64/32/16-ring subsets and elevation-matched target angular profiles?
\end{enumerate}

\textbf{Contribution.} The new contribution is a reproducible evaluation design that connects four views usually reported separately: detection accuracy, prepared-frame inference cost, object support by range and point count, and paired sparsity sensitivity. It also provides a controlled capacity comparison through PointPillars Lite and separates geometric decimation from target-angle matching with dense field-of-view controls. We do not claim a new detector, a new beam-density concept, or a complete physical-sensor simulation. All completed empirical claims use one seed-42 checkpoint per configuration, so small differences remain descriptive.

The remainder of the paper reviews related work, defines the benchmark, describes training and measurement procedures, reports the completed single-seed comparison, and discusses threats to validity. All empirical values correspond to one checkpoint per configuration.

\section{Related Work}

PointPillars groups points into vertical columns, learns pillar features, and applies a two-dimensional convolutional backbone to a bird's-eye-view representation \cite{lang2019pointpillars}. SECOND uses sparse convolution over voxelized features \cite{yan2018second}. These approaches motivate a comparison between pillar and three-dimensional voxel representations under a common input domain. PillarNet further demonstrates that pillar-based detection is a broader architectural family rather than a single fixed accuracy--efficiency profile \cite{shi2022pillarnet}.

CenterPoint represents objects through their centers and regresses their attributes \cite{yin2021centerpoint}. Our implementation uses the configured single-stage detector; the name does not imply that every component of the original detection-and-tracking system is evaluated. VoxelNeXt predicts from sparse voxel features \cite{chen2023voxelnext}; the benchmark configuration retains its configured decoding and non-maximum suppression (NMS). PV-RCNN combines voxel features with point-based feature abstraction and proposal refinement \cite{shi2020pvrcnn}. These categories overlap: representation, prediction-head design, and refinement are distinct dimensions. With one configuration per named model, the study compares complete detector configurations and cannot estimate a causal effect of an architectural family alone.


KITTI, nuScenes, and the Waymo Open Dataset have established widely used evaluation settings for autonomous-driving perception \cite{geiger2012kitti,caesar2020nuscenes,sun2020waymo}. Their metrics, class definitions, and data distributions are not interchangeable. KITTI's current object-detection evaluation uses 40 recall positions \cite{kitti_eval}; adopting 40 positions does not make a custom matching implementation equivalent to KITTI or to an official Boreas score.

Boreas is a multi-season autonomous-driving dataset \cite{burnett2023boreas}. This paper uses the sunny-condition annotations in Boreas-Objects-V1. A local validation subset is carved from official training intervals, and the official test intervals are not used. Accordingly, comparisons are internal to the disclosed partition. They do not establish a ranking on the official hidden test set or on unlabeled winter sequences.

Adverse-weather research provides useful context but addresses an additional problem. CADC contains adverse driving conditions \cite{pitropov2021cadc}. Gupta et al. study all-weather LiDAR perception, including experiments using Boreas data \cite{gupta2025allweather}. Matteazzi et al. investigate adverse-weather augmentation with latent diffusion models \cite{matteazzi2026augmentation}, and the associated B-3DOD-B-AWC resource provides supplementary detection data \cite{boreas_awc}. These works preclude a general claim that LiDAR detection on Boreas has not been studied. Weather evaluation would require an explicitly incorporated labeled resource and a separate protocol; it is outside the present experiments.


Robo3D and the common-corruption detection benchmark examine robustness beyond standard clean-data evaluation \cite{kong2023robo3d,dong2023corruptions}. Eskandar et al. investigate the interaction of architectural and training choices with generalization to unseen domains \cite{eskandar2024generalization}. Their findings motivate reporting augmentation, voxel encoding, and anchor choices alongside accuracy.

LiDAR Distillation explicitly addresses beam-induced domain gaps \cite{wei2022lidardistillation}. Griesbacher and Fruhwirth-Reisinger investigate beam density, including dense 128-beam data \cite{griesbacher2025beamdensity}. Feng et al. study beam loss with a focus on vulnerable road users \cite{feng2026beamloss}. Our primary RQ4 design freezes the dense-input checkpoint and changes only the retained ring subset. It estimates sensitivity to this intervention, rather than performance after adaptation. Its intended value is the combination with class- and range-resolved accuracy and measured computational cost on a disclosed Boreas partition.



\section{Experimental Design}
\label{sec:benchmark}
\subsection{Data and configurations}
Each frame is a point set
\begin{equation}
\mathcal{P}=\{(x_i,y_i,z_i,I_i)\}_{i=1}^{N},
\end{equation}
where $I_i$ is the provided intensity. The detector returns scored upright oriented boxes
\begin{equation}
\begin{aligned}\mathcal{D}&=\{(b_j,c_j,s_j)\}_{j=1}^{M},\\ b_j&=(x,y,z,d_x,d_y,d_z,\theta).\end{aligned}
\end{equation}
The target classes are Car, Pedestrian, and Cyclist. Ring IDs are used during offline subsampling but are not network input features. Per-point timestamps are not input features, and the exporter applies no additional motion deskewing. The protocol uses a single LiDAR frame without camera input, accumulated sweeps, or tracking.

The shared point-cloud domain is
\begin{equation}
[-75.2,75.2]\times[-75.2,75.2]\times[-3,5]\ \mathrm{m}.
\label{eq:domain}
\end{equation}
The label exporter retains boxes whose centers satisfy $x,y\in[-75,75)$ and $z\in[-3,5)$. Thus, the annotation-center crop is slightly narrower than the point-cloud domain in the horizontal axes. This boundary convention is retained and disclosed. Models may subsequently apply their configured training-time box-range filters after augmentation. Intensity is exported without an additional normalization transform.


The partition uses the 37 official object-training temporal intervals listed by the Boreas development kit \cite{pyboreas}. Interval order is preserved. Zero-based indices $0,5,10,15,20,25,30,35$ define validation; the remaining 29 intervals define training. Entire intervals are assigned to a partition. Consecutive frames are not randomly distributed between training and validation.

A training frame is removed if its timestamp is within two seconds of any validation interval. The prepared nominal 128-beam data contain 3,607 training and 1,326 validation frames (Table~\ref{tab:data}). The 16 official test intervals are excluded from this study. The split manifest, frame identifiers, interval list, and exclusion rule should accompany the benchmark release. \pending{Record the exact pyboreas version and the hash of the ordered interval list in the release manifest.}

The temporal buffer reduces direct adjacency between training and validation observations. It does not guarantee spatial independence, because traversals may observe the same route or scene structure. This is a fixed local validation design, not an independent geographic test. The eight validation intervals are the natural clustering units for any subsequent interval-level analysis.

For each beam condition, identical frame identifiers, class names, and ground-truth boxes are retained. Objects are not removed from evaluation merely because subsampling leaves them with few or no observed points. Such cases are part of the robustness experiment. Input membership and annotation consistency are checked before inference.

PointPillars Lite halves the pillar feature width from 64 to 32, changes the BEV backbone widths from $(64,128,256)$ to $(32,64,128)$, and changes the three upsampling output widths from 128 to 64 each. Layer counts and the remaining parent configuration are retained. This provides a controlled capacity comparison with PointPillars. It is not introduced as a new architecture or given an independent novelty claim.

The shared input domain does not imply identical retained point sets inside each network. Pillar configurations allow 32 points per cell and 80,000 occupied cells; voxel configurations allow 10 points per cell and 200,000 occupied cells. Truncation and discretization are part of each tested configuration. Identical limits would not equate the representations, but unreported limits could confound interpretation.


All configurations share frame partitions, target classes, raw input features, spatial domain, augmentation family, epoch budget, and evaluation code. Augmentation consists of world flips along the $x$ and $y$ axes, rotation sampled within $[-\pi/4,\pi/4]$, and scaling within $[0.95,1.05]$. Point order is shuffled during training and retained during evaluation. Ground-truth database sampling, weather augmentation, and beam-drop augmentation are absent from the primary experiment.

Model-specific learning rates, clipping thresholds, and NMS thresholds are preserved and explicitly reported (Appendix~\ref{app:config}). The current final NMS candidate and output caps are 4,096 and 500, respectively. Proposal-stage processing in PV-RCNN and decoder-specific candidate selection remain model-specific. These choices define a comparison of configured systems under shared external conditions. They do not support an assertion that all low-level processing choices are identical.

\subsection{Evaluation protocol}
The primary score is local 3D $\mathrm{AP}_{40}$ at IoU 0.7 for Car and 0.5 for Pedestrian/Cyclist. Predictions are globally score-ordered and matched to an unmatched same-class target; unmatched predictions overlapping Misc are ignored. Overall $\mathrm{mAP}_{40}$ is the unweighted class mean. Precision, recall, and F1 use score 0.1.

Range bins are $[0,20)$, $[20,40)$, $[40,60)$, and $[60,\infty)$ m. Point-count cohorts are 0, 1--5, 6--20, 21--50, 51--100, and at least 101 points. Primary cohort membership is fixed from dense input so sparse conditions cannot reassign difficult objects. Full matching, AP, range-boundary, and cohort definitions are retained in Appendix~\ref{app:metrics}.

Modulo subsets keep $r_i\bmod(128/K)=p$ for $K\in\{64,32,16\}$ and every valid remainder $p\in\{0,\ldots,128/K-1\}$, giving 2/4/8 phases at 64/32/16 rings. The dense condition retains all 128 rings. Elevation matching uses source-ring medians estimated from 20 training frames and an order-preserving one-to-one assignment to published VLP-16/VLP-32C profiles \cite{velodyne_profiles}. Dense controls retain all source rings inside the same vertical FOV. These interventions preserve checkpoints and labels; they do not simulate horizontal resolution, firing timing, return physics, noise, or intensity transfer.

\subsection{Efficiency measurement}
FP32 batch-one profiling on one RTX 5060 Ti includes prepared-frame loading, CPU preprocessing, host-to-device transfer, detector execution, decoding, and postprocessing. Mean, p50, p95, serial FPS, parameters, and peak CUDA memory are measured over 200 selected frames after 20 warmup frames. Sensor acquisition, raw Boreas conversion, weight loading, visualization, and serialization are excluded. Dense accuracy--speed and accuracy--memory Pareto frontiers use these measurements; sparse latency is not inferred from ring count. Measurement equations and memory semantics appear in Appendix~\ref{app:metrics}.

\subsection{Training and record keeping}
All six seed-42 manifests record Adam with a one-cycle schedule, weight decay 0.01, effective batch size four, AMP, two workers, and 80 epochs. Shared augmentation comprises $x/y$ flips, rotation in $[-\pi/4,\pi/4]$, and scaling in $[0.95,1.05]$; ground-truth sampling and beam-drop augmentation are absent. Model-specific learning rates, clipping, NMS, occupancy limits, and loss weights are listed in Appendix~\ref{app:config}.

The fixed epoch-80 checkpoint is reused for every validation condition. Re-evaluation provides paired input comparisons, not independent training realizations. No across-run mean, confidence interval, or rank-stability probability is estimated. Multiphase means, sample standard deviations, and ranges summarize input-offset sensitivity only.

Predictions retain frame IDs, boxes, classes, scores, checkpoint/configuration identities, and hashes. The audit checks common ground truth, FP32 inference settings, cutoff, caps, TF32 flags, and sampling manifests. Missing historical source/environment fields are disclosed rather than inferred.

\section{Results}
\label{sec:results}
The experiment comprises six seed-42 epoch-80 checkpoints, 114 validation evaluations (19 evaluation conditions per model), and six nominal 128-ring profiling runs. All conditions use the same 1,326 frames and target-box fingerprint. The audit verifies actual checkpoint and saved-prediction SHA-256 hashes against the AP, extended-metric, and inference reports, and checks common FP32 precision, evaluation seed, cutoff, caps, and TF32 flags. Angular and modulo-phase reports also match their sampling manifests. Each model contributes one training realization; all 19 evaluation conditions reuse that checkpoint.

\subsection{Dense accuracy and efficiency}
Table~\ref{tab:main} orders the dense configurations as PV-RCNN (59.11), PointPillars (53.80), Lite (49.66), SECOND (48.50), VoxelNeXt (47.10), and CenterPoint (46.29) in local mAP40. PV-RCNN exceeds PointPillars by 5.31 percentage points and leads Car and Pedestrian AP at 59.73 and 67.79. PointPillars leads Cyclist AP at 50.04, compared with PV-RCNN's 49.81: the 0.23-point difference is descriptive and cannot establish a repeatable advantage from one checkpoint.

Class performance explains why aggregate rankings are insufficient. SECOND exceeds PointPillars on Car AP (50.69 versus 46.95), whereas PointPillars is stronger on Pedestrian (64.41 versus 56.34) and Cyclist (50.04 versus 38.45). CenterPoint's Cyclist AP (48.92) exceeds that of SECOND, Lite, and VoxelNeXt, despite its lowest aggregate mAP. Its Pedestrian AP of 41.66 limits the aggregate score.

Lite has 1.217 million parameters versus PointPillars' 4.835 million, a 74.82\% reduction. Its mAP is 4.14 points lower, but mean latency decreases from 61.40 to 46.32 ms (24.56\%) and peak allocated memory from 1,543.18 to 876.43 MiB (43.21\%). This is an observed capacity--cost pairing under the common seed-42 protocol, not an estimate of its variability over training runs.

Thus SECOND and Lite represent different choices; SECOND does not dominate Lite on accuracy and speed. The accuracy--speed frontier contains SECOND, Lite, PointPillars, and PV-RCNN. The accuracy--allocated-memory frontier contains VoxelNeXt, SECOND, Lite, and PV-RCNN.

PV-RCNN's 59.11 mAP costs 310.81 ms mean latency: 269.94 ms more, or 7.61 times SECOND's latency, for a 10.62-point aggregate gain. Its 280.68 ms full-forward stage accounts for 90.31\% of measured E2E time. In SECOND, preparation plus transfer consumes 20.53 ms, about 50.23\% of E2E time. Consequently, network acceleration alone cannot remove the preparation cost under this serial boundary. Components include synchronized execution and configured postprocessing, rather than a network-only comparison .

CenterPoint and VoxelNeXt differ by only 0.63 ms in mean E2E latency (48.54 versus 49.18); one profiling pass provides insufficient evidence for a stable speed advantage of that size. Reported p95 values describe the selected frames, not hard deadlines or uncertainty across profiling repetitions. Under an illustrative p95 limit of 50 ms and a 256 MiB allocated-memory budget, only SECOND is feasible. With limits of 75 ms and 2,048 MiB, PointPillars has the highest measured feasible mAP. These examples use dense-input profiles; sparse latency was not measured and must not be inferred from ring count.

\subsection{Beam sparsity and angular profiles}
Table~\ref{tab:robustness} shows large losses despite retaining the same checkpoint and labels. At modulo-16, PV-RCNN falls from 59.11 to 18.20 mAP, an absolute loss of 40.91 points but the highest retention (30.79\%). PointPillars retains 29.61\% (15.93 mAP); Lite and SECOND retain 26.99\% and 26.83\%. VoxelNeXt and CenterPoint retain only 15.12\% and 13.51\%, respectively. Absolute loss and relative retention answer different questions: the highest dense score can have the largest absolute decrease while remaining the best sparse aggregate score.

For the phase-zero subsets in Table~\ref{tab:robustness}, the aggregate order is unchanged at modulo-64 and modulo-16: PV-RCNN, PointPillars, Lite, SECOND, VoxelNeXt, CenterPoint. At modulo-32, SECOND (30.10) overtakes Lite (29.08). The complete offset analysis below shows that this local swap is phase-specific rather than representative of the mean ordering. PV-RCNN remains first and PointPillars second in every phase-zero modulo condition.

Class-specific degradation also changes the preferred model. At modulo-16, PV-RCNN leads Car and Cyclist AP (17.92 and 14.19), but PointPillars leads Pedestrian AP at 28.22, followed by Lite at 25.34 and PV-RCNN at 22.50. A dense aggregate leader therefore need not be the strongest choice for sparse Pedestrian detection.

\section{Discussion and Limitations}
The benchmark exposes a three-way trade-off. PV-RCNN gives the highest dense accuracy at much greater latency; SECOND gives the fastest measured service time and low allocated memory; PointPillars and Lite occupy intermediate accuracy--cost positions. Parameter count alone does not predict latency or memory because preprocessing, representation, occupancy, decoding, and implementation all contribute.

The paired experiments show that dense-trained detectors can lose most of their AP and recall as vertical support is reduced. Nominal channel count is insufficient to predict the outcome: modulo and elevation-matched layouts produce different rankings and class behavior. Dense-FOV controls narrow the explanation but do not isolate layout from point count or object coverage. The complete offset sweep further shows that phase selection can move 16-ring mAP by 3.88--7.20 points within a fixed checkpoint and that a phase-zero rank reversal need not persist in the phase mean. Matched-density retraining would answer a separate adaptation question.

Five limitations bound the claims. First, one seed-42 training realization per configuration cannot estimate optimization variance, confidence intervals, or rank stability. Second, the local sunny-condition split is neither the official hidden test nor an adverse-weather evaluation, and temporal buffering does not ensure geographic independence. Third, local AP40, Misc handling, export cutoff, output caps, and center-based range filtering are study-specific. Fourth, elevation matching omits horizontal resolution, firing timing, motion, noise, return physics, and intensity transfer. Fifth, latency reflects one RTX 5060 Ti, one software stack, 200 frames, and one profiling pass. Missing historical environment fields are disclosed rather than reconstructed.

These limits still permit within-checkpoint paired comparisons. Large losses and broad resource gaps are informative; small differences remain descriptive until independent training and profiling repetitions are available.

\section{Conclusion}
One seed-42 checkpoint per configuration yields a clear measured accuracy--cost trade-off on local Boreas-Objects-V1 validation. PV-RCNN reaches 59.11\% dense mAP40 at 310.81 ms mean latency; SECOND reaches 48.50\% at 40.87 ms, and Lite reaches 49.66\% at 46.32 ms. PointPillars leads dense Cyclist AP and offers 53.80\% aggregate mAP, while Lite reduces its parameter count by 74.82\% at a 4.14-point mAP decrease.

Modulo-16 phase zero retains only 13.51--30.79\% of dense mAP and sharply reduces Pedestrian recall, especially for fixed 21--50-point cohorts. Across all offsets, the phase-averaged ordering is stable at 64, 32, and 16 rings; Lite remains above SECOND at 32 rings despite the phase-zero reversal. At 16 rings, every model's aggregate mAP40 is highest at phase 4 and lowest at phase 3, with within-model ranges of 3.88--7.20 points. Elevation-matched profiles reveal additional layout sensitivity: PointPillars leads VLP-16 mAP at 11.20\%, and VLP-32C changes AP relative to modulo-32 in a model-dependent direction. AP, recall, class/range performance, latency, and memory should therefore be read together. These are descriptive single-checkpoint findings; independent training repetitions and more controlled sampling ablations are needed to assess repeatability and isolate mechanisms.

\section{Metric and Measurement Details}
\label{app:metrics}
For oriented boxes $b$ and $g$, $\operatorname{IoU}_{3D}=V(b\cap g)/(V(b)+V(g)-V(b\cap g))$. Predictions use deterministic score tie breakers and one-to-one same-class matching. At recall samples $j/40$,
\begin{equation}
\mathrm{AP}_{40}(c)=\frac{100}{40}\sum_{j=1}^{40}\max_{k:R_k\ge j/40}P_k.
\end{equation}
Saved predictions use cutoff 0.001; operating-point metrics use 0.1. Misc boxes can suppress unmatched predictions but are never positives. Range AP filters prediction and target centers independently, which can create boundary mismatches.

Point support counts retained points inside each oriented ground-truth box before model-specific voxelization. Full-domain matches define cohort recall. Density remains observational because range, size, and occlusion also affect point count. Objects and labels remain in sparse evaluation even when no returns survive.

Prepared-frame latency is $T_{\mathrm{E2E}}=T_{\mathrm{prep}}+T_{\mathrm{H2D}}+T_{\mathrm{forward}}$, where forward includes decoding and configured postprocessing. CUDA synchronization surrounds measurement, and serial FPS is $1000/\overline{T}_{\mathrm{E2E}}$ in milliseconds. Peak allocated/reserved memory includes model tensors and allocator behavior but is not total external process memory. Legacy KITTI-style and BEV outputs remain supplementary because the adapter does not reproduce genuine KITTI image difficulty strata.

\subsection{Training loss functions and weights}
\label{app:loss}
Table~\ref{tab:loss-config} records the loss weights from the archived effective configurations of the six seed-42 runs. Component definitions follow the corresponding OpenPCDet head implementations. The benchmark retains these model-specific objectives rather than imposing a common numerical loss scale across architectures.

\paragraph{Anchor-based dense heads.}
PointPillars, SECOND, PointPillars Lite, and the PV-RCNN proposal head use sigmoid focal classification loss with $\alpha=0.25$ and $\gamma=2$, Smooth L1 regression on seven encoded box residuals with transition parameter $\beta=1/9$, and cross-entropy classification of two direction bins. Their dense-head objective is
\begin{equation}
\mathcal{L}_{\mathrm{anchor}}
=\mathcal{L}_{\mathrm{cls}}+2\mathcal{L}_{\mathrm{box}}
+0.2\mathcal{L}_{\mathrm{dir}}.
\end{equation}
All seven regression code weights are one. The yaw residual uses the implementation's sine-difference transform. Classification includes valid positive and negative anchors, whereas regression and direction loss use positive anchors. Anchor losses are normalized by the positive-anchor count in each frame, clamped to at least one, and then averaged over the batch.

\paragraph{Center-based dense heads.}
CenterPoint and VoxelNeXt use a modified focal loss on Gaussian center heatmaps, with prediction-focusing exponent 2 and negative-target weight $(1-y)^4$, together with masked L1 box regression. CenterPoint evaluates a dense heatmap; VoxelNeXt evaluates its sparse counterpart. Their objectives are
\begin{align}
\mathcal{L}_{\mathrm{CP}}&=\mathcal{L}_{\mathrm{hm}}+\mathcal{L}_{\mathrm{box}},\\
\mathcal{L}_{\mathrm{VN}}&=\mathcal{L}_{\mathrm{hm}}+0.25\mathcal{L}_{\mathrm{box}}.
\end{align}
All eight regression code weights are one, covering horizontal center offsets, height, three dimensions, and sine/cosine yaw. Heatmap loss is normalized by the number of exact positive centers when nonzero; with no positive centers it retains the summed negative term. Regression ignores invalid targets and is normalized by the valid target count, clamped to at least one. Neither configuration enables an additional IoU prediction or IoU regression loss.

\paragraph{PV-RCNN point and refinement heads.}
PV-RCNN adds point classification and ROI refinement to its anchor-based proposal objective:
\begin{equation}
\begin{aligned}
\mathcal{L}_{\mathrm{PV}}={}&\mathcal{L}_{\mathrm{anchor}}
+\mathcal{L}_{\mathrm{point\text{-}cls}}\\
&+\mathcal{L}_{\mathrm{ROI\text{-}cls}}
+\mathcal{L}_{\mathrm{ROI\text{-}box}}
+\mathcal{L}_{\mathrm{corner}}.
\end{aligned}
\end{equation}
The configured \texttt{PointHeadSimple} uses sigmoid focal classification with $\alpha=0.25$, $\gamma=2$, and unit weight, normalized by the positive-point count clamped to at least one. It has no active point-regression term. ROI classification uses binary cross-entropy on logits and averages over nonignored sampled ROIs. ROI regression uses Smooth L1 ($\beta=1/9$) on seven residuals with unit code weights and normalizes over foreground ROIs. Corner regularization is enabled: Smooth L1 with $\beta=1$ is applied to corner distances using the smaller distance to the target orientation or its $\pi$-rotated equivalent, then averaged over corners and foreground ROIs. ROI classification, box regression, and corner regularization each have weight one.
